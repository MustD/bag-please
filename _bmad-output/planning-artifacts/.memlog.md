- (event) Update run started from docs/feedback.md (6 user-feedback items: in-app feedback, multi-store items, admin
  user pagination, category filter confirm, FAB quick-add, home link in menu)
- (decision) [bootstrap] Epic 4 introduces personal lists with sharing: all items/categories become scoped to a specific
  list, ending the previous globally-shared data model.
- (decision) [bootstrap] Existing unscoped items/categories are migrated on first Epic 4 startup to a default
  'Groceries' list owned by the most recently created non-admin user; startup hard-fails if no non-admin user exists
  (FR47).
- (decision) [bootstrap] Admin account is excluded entirely from lists (FR56): all list-related GQL operations reject
  admin callers, enforced at the service layer, not just routing.
- (decision) [bootstrap] Migration is idempotent via an app_migrations completion record so repeated restarts after
  migration are no-ops (NFR-L3).
- (decision) [bootstrap] List sharing uses a pending-invite model (FR39): sharing creates an invite the invitee must
  Accept/Reject; the list is inaccessible until accepted.
- (decision) [bootstrap] List members have full peer write access with no owner/member role distinction on items; only
  the owner can delete the list, and cascade-delete removes all its items and categories (FR37, FR40).
- (decision) [bootstrap] Non-owner members can leave a shared list at any time (FR55); their items remain on the list
  after leaving or being removed.
- (decision) [bootstrap] Item save is a merge, not a reconstruction (FR58): addedBy, checkedAt, and deleted survive an
  edit; create-vs-update is discriminated by whether the item id already exists on the target list, never by
  presence/absence of an id, since the client always generates the id via crypto.randomUUID () even for creates.
- (decision) [bootstrap] FR58's earlier draft (reject any item id not found on the list) was overruled by md on
  2026-07-29 because it would have rejected every new item; the corrected rule creates on not-found, merges on found,
  and rejects ids found on a different list or referencing a foreign category.
- (decision) [bootstrap] FR59 (installable PWA, Chrome-on-Android WebAPK via manifest + PNG icons + service worker) was
  added because FR57's in-app home affordance becomes load-bearing once there is no browser back button in an installed
  app; no offline capability is implied.
- (decision) [bootstrap] Epic 5 re-implemented the frontend from scratch on Vite + Material UI served by Caddy,
  replacing Next.js + nginx, with the Ktor/GraphQL backend unchanged and no functional requirement changes.
- (decision) [bootstrap] Epic 5 deferred one-timer (FR42) and recurring (FR43) item UI affordances (backend support
  kept) while keeping real-time collaboration (FR52/FR53).
- (decision) [bootstrap] FR48 (bottom-tab navigation chrome) and FR49 (Today tab category-group/completion behavior) are
  superseded: they describe the Epic 4 bottom-tab design that never shipped; Epic 8's Story 8.7 replaces both stale UX
  specs with a DESIGN.md + EXPERIENCE.md spine describing what is actually deployed.
- (decision) [bootstrap] FR60 (Epic 8) makes the entire shopping-view item row the check-off activation target, not just
  the checkbox, and it is exposed as a single accessible control (one name, one state, one tab stop).
- (decision) [bootstrap] FR61 (Epic 8) requires category filtering and free-text item search on both the shopping view
  and management view with identical controls/semantics; the category filter accepts multiple categories (AND with
  search, OR across selected categories); the checked-status toggle stays shopping-view-only.
- (decision) [bootstrap] FR62 (Epic 8) requires categories and their items to be ordered identically (by name) on both
  the shopping view and the management view, so switching screens preserves the same sequence.
- (decision) [bootstrap] FR63 (Epic 8) added category rename from the list management screen after md reported that a
  mistyped category name previously could only be fixed by deleting the category (destroying its items); verified as
  needing no backend change since saveCategory is already an id-keyed upsert.
- (decision) [bootstrap] NFR64/NFR65 (Epic 8) establish 320px as a supported viewport floor, driven by a foldable cover
  display (~344px), and require the E2E suite to mechanically assert no overflow/clipping at that width on every
  phone-emulating project rather than relying on visual inspection.
- (decision) [bootstrap] NFR17 was corrected on 2026-07-30 to replace a stale nginx reference with the actual production
  artifact (Caddy-served SPA), add mandatory desktop+mobile viewport coverage, and widen the zero-failures gate from
  Epic 1/2 stories to any story in any epic.
- (decision) [bootstrap] NFR18 was reversed on 2026-07-30: it originally mandated an API-login fixture, which
  contradicted AR-E7-5/Story 7.2 AC3; it now requires UI-driven auth per spec (fresh user, no login fixture, no
  storageState), with direct API calls allowed only for environment setup, never for the behavior under test.
- (decision) [bootstrap] NFR17/NFR18 had never been carried into epics.md's requirements inventory despite being in the
  PRD, which is why the login-fixture contradiction survived three epics before being caught; both are now recorded in
  both documents.
- (decision) [bootstrap] Admin account credentials are supplied via environment variables only, never stored in the
  database, and there is deliberately no recovery path if lost (FR18/FR19).
- (decision) [bootstrap] Public self-registration defaults to off; admin manually onboards users at this stage, and the
  registration link is hidden from the login screen whenever the toggle is off (FR20/FR21).
- (decision) [bootstrap] Refresh tokens are delivered only via httpOnly, SameSite=Strict cookies (never accessible to
  JS); access tokens are held in memory/Apollo context, not localStorage, to keep the refresh cookie invisible to JS.
- (decision) [bootstrap] Passwords are hashed with bcrypt cost factor 12; access tokens are short-lived (15 min) and
  refresh tokens long-lived (30 days), stored in MongoDB with a TTL index (NFR1-NFR4).
- (decision) [bootstrap] An hourly background scheduler (FR54) restores recurring items on cadence (weekly=7d,
  biweekly=14d, monthly=30d, one restoration per run regardless of missed cycles) and hard-deletes one-timer items
  soft-deleted for more than one hour.
- (decision) [bootstrap] WebSocket subscriptions require a valid JWT in connectionParams; the backend rejects
  unauthenticated connections and closes on token expiry, and events are filtered per-list so no cross-list event
  leakage occurs (FR53, NFR-L1, NFR-L5).
- (decision) [bootstrap] Every service-layer method touching list-scoped data must verify caller membership before any
  access, including reads, with no exceptions (NFR-L2); unauthorized access returns a GQL error rather than an empty
  result (NFR-L4).
