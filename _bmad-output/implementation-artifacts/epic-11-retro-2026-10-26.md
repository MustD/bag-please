**F9. `db:bootstrap` says it is idempotent, but it refuses after the import.** (edge-case)
- Source: `deploy/scripts/bootstrap-db.sh:2` ("one-time, idempotent") and `:27-29`. Bootstrap runs Flyway by calling
  `run_importer` on an empty export. `MongoImport.run` (`MongoImport.kt:283-287`) then refuses any non-empty target,
  so a second `db:bootstrap` against the production database exits 1 with "Import refused: Target database is not
  empty".
- Consequence: the GRANTs re-apply, but the script reports a failure. An operator re-running it to repair grants sees
  an alarming "import" error.
- Disposition: **defer** (low). Either change the comment to "idempotent until the import", or have bootstrap call
  `migrate()` directly.

**F10. `unset_deploy` strips the names in the committed examples, not the variables in the real secure files.**
(adversarial / claim)
- Source: `lib.sh:23-36` (`secure_names` greps `.secure.*.env.example`). Story 11.10 AC: "every variable defined in
  `.secure.deploy.env` … is stripped first". Root `CLAUDE.md`: "`lib.sh` strips every variable of both files".
- Consequence: a secret added to `.secure.deploy.env` but not to the example, outside the `TF_VAR_*`/`KTOR_*`
  prefixes, reaches nested Gradle, mise and java. `test-guards.sh:116-124` only checks that `require_env` names
  appear in the example, so it cannot catch this drift.
- Disposition: **defer** (low). Derive the names from the real file when it exists, or add a guard that fails when
  the real file declares a name the example lacks.

**F11. The importer loads legacy states it knows are broken, without reporting them.** (edge-case)
- Source: `MongoImport.kt:250-256`. It loads `checked`, `recurring`, `checkedAt`, `deleted` and `deletedAt` as found.
  `401614e` adds Mongo-era defaults for missing fields.
- Consequences:
  - A recurring item with `checked = true, checkedAt = null`, the pre-9.5 shape `ItemService.kt:63-69` describes, is
    skipped forever by `restoreRecurring` (`ItemService.kt:224`).
  - `deleted = true, deletedAt = null` is never selected by `findSoftDeletedBefore`.
  - A missing `createdAt` on lists, memberships or feedback becomes `Instant.now()` (`:168, :197, :262`).
  - None of these appear in the report, which counts loaded and dropped rows only.
- Disposition: **defer** (low; the import has run). One SQL check against production tells whether any such rows
  exist: `select count(*) from items where (checked and recurring in ('WEEKLY','BIWEEKLY','MONTHLY') and checked_at is
  null) or (deleted and deleted_at is null)`.

**F12. `deploy.sh` prints no rollback hint for failures before its trap is installed.** (edge-case)
- Source: `deploy.sh:18-33` (version and tag checks, `tf_init`, `load_runtime_outputs`) run before `trap on_exit
  EXIT` at `:44`.
- Consequence: harmless, because the droplet is untouched at that point. It is still a gap against the 11.10 AC "on
  any failure it prints the rollback command".
- Disposition: **accept.** Record it as an accepted deviation.

**F13. `deleteUser` can still race a `createList` from the deleted user.** (adversarial)
- Source: `UserService.kt:146-155`. The 11.2 deferral (spec frontmatter) was partly closed by 11.4: the purge now runs
  in one `tx`. `createList` (`ListService.kt:89-104`) does not lock the user row, though. A `createList` committing
  between `purgeUser` and `deleteById` makes the `users` delete fail on `lists.owner_id ON DELETE RESTRICT`.
- Consequence: the admin's delete rolls back with a server error, and the data stays consistent.
- Disposition: **accept.** The app has two users, and the failure mode is a retry.

**F14. Per-store test files duplicate per-behaviour test files.** (pattern divergence)
- Source: the new `ItemPostgresTest.kt` (355 lines) beside `ItemLifecycleTest.kt` (1,485 lines, 45 flat `test(`
  blocks, 0 `context(`), and `CategoryPostgresTest.kt`, `ListPostgresTest.kt` and `AccountsAndSessionsPostgresTest.kt`
  beside their behaviour suites. The suffix names a store that is now the only store.
- Disposition: **defer.** Fold this into the Epic 9 item 43 split of `ItemLifecycleTest.kt`.
