## What Went Well

### The dependency ladder held its sequencing discipline through seven majors

Each major landed as one commit, verified green alone, before the next started. The epic forbade bundling and it never
happened once. `git show --stat` was used as the proof at every rung, not as a formality:

- **7.8** `@types/node` 25.9.5 → 26.2.0 — exactly two files. The shipped chunk was **byte-identical** to baseline, which
  is the right answer for a compile-time-only package and a stronger result than a green suite.
- **7.9** Vite 7 → 8 **with** `@vitejs/plugin-react` 5 → 6, deliberately in the same commit because either alone breaks
  the build. esbuild and rollup left the tree; rolldown + lightningcss came in.
- **7.11** ESLint 9 → 10 — `eslint.config.mjs` **unchanged**, no plugin moved, and the shipped bundle came out at the
  same filename hash and the same size. A linter that ships nothing into the artifact should leave the artifact alone,
  and it did.
- **7.12** the epic's highest-risk bump: `graphql-kotlin` 9.3.0 → 10.2.1 dragging Kotlin 2.3.21 → 2.4.10, graphql-java
  23.1 → 25.0 and Jackson 2 → Jackson 3 simultaneously — landed at the **top ladder rung**, green first try, with **zero
  backend source change**. One file, two lines.
- **7.13** `graphql` 16 → 17 with all four `__generated__` files coming out byte-identical — and the instrument that
  proved it was falsified first.

Charlie (Senior Dev): *"Seven majors, and every single one is independently attributable. That's the property the
sequencing existed to buy, and we actually got it."*

### A hold became a deliverable rather than an excuse

Story 7.10 closed `done` with TypeScript pinned at 6.0.3 and 7.0.2 unattained. What makes that legitimate is that the
symptom was **reproduced in the real tree**, not cited from a peer-range string — and the reproduction contradicted the
plan: `npm install typescript@7.0.2` *succeeds*, exit 0. The peer conflict does not stop you; the runtime does.
`npm run lint` then exits 2 having linted **zero files**, dying at module load with
`typescript-eslint does not support TS 7.0`. A sweep of all 83 published `typescript-eslint` ≥ 8.0.0 releases shows the
`typescript` peer takes exactly four values and **none** admits 7.x — there is no version to move to, not merely no
stable one.

And the hold produced a finding worth more than the bump would have: **the codebase is already TS-7-clean.** With 7.0.2
actually installed, `tsc -b --force` exits 0 with zero diagnostics under unchanged `strict`, `noUnusedLocals`,
`noUnusedParameters`, `noFallthroughCasesInSwitch` — no `@ts-expect-error`, no weakened option, no `tsconfig` touched.
The hold is about the linter, not the code, and the eventual bump is expected to be a one-line change.

The documented dual-TypeScript workaround was refused on three recorded costs rather than quietly skipped.

### Falsification became routine — Epic 6's dominant finding largely fixed

Epic 6's worst pattern was *"assertions that could not fail"* — six of seventeen review patches. Epic 7 attacked it
directly:

- **7.11** discharged both behavioural ACs by injecting real violations and watching lint go red, then reverted — and
  re-measured the const trap rather than quoting it: `export const bpProbeConst = 1` is **silent** under
  `allowConstantExport`, so a const-shaped probe would have been vacuous. The E2E half needed no injection at all: its
  silence *is* the live falsification, because `e2e/support/ui.ts` exports the exact shape that had just failed in
  `src/`.
- **7.14** falsified three review-added assertions before trusting them — deleting the Caddy `Cache-Control` line,
  adding `orientation: 'portrait'`, and re-rasterising the maskable icon full-bleed each reddened the intended test.
- **7.4** re-observed the backend red itself in a second session rather than inheriting the first session's claim.

### The gate became real, in the right order

7.1 put `e2e/` inside both static gates. 7.2 collapsed four copies of the helpers into one module. 7.3 **deleted** the
`registrationEnabled` race instead of retrying it — genuine *cross-project* exclusivity via two chained
`registration-toggle-*` projects, because per-file serial mode only serializes within a project — and removed the
`toPass` workaround in the same change, so the next flake cannot hide behind it.

Dana (QA Engineer): *"After 7.3 the suite could actually fail. And in 7.9 it did, informatively, which is the whole
point of having built it."*

### Measurement beat recollection, consistently

Every dependency story re-derived registry state in its own pass and **diverged from the epic's named versions** —
`@types/node` 26.2.0 not 26.1.2, Vite 8.2.1 not 8.1.5, and so on — each time recorded as a divergence rather than
silently pinned down. Story 7.2 re-measured the duplication and found the epic's `Files:` line understated it
(7/6/5/4/4/4/2/2, not 4 across the board). Story 7.4 found **12** of the story file's figures and line numbers wrong and
tabled the corrections because the wrong file loads as context beside the spec.

Winston (Architect): *"The planning documents went stale during their own epic, and the epic survived it because nothing
was allowed to be quoted."*

## What Didn't Go Well

### 1. The review pass is doing the epic's real quality work — and it is finding prose defects, not code defects

This is the epic's dominant finding. **All 15 specs** closed `followup_review_recommended: true`, and their own
frontmatter says why with unusual consistency:

- **7.1** — *"8 patches (4 medium) all landed in the documentation/bookkeeping ~80% of the diff that no gate checks —
  including two factually false ledger prescriptions and a rules-file correction; that text is read as authoritative by
  later agents."*
- **7.3** — *"11 patches (8 medium) and 8 of them landed in newly written authoritative prose — a false mobile-gate
  claim, a recovery command that could not work, a false 'only construct' claim, an over-read measurement propagated to
  three documents, and a ledger action item aimed at a CI pipeline that does not exist."*
- **7.14** — both reviewers independently found the same top defect and it was a **documentation inversion**: the code
  did the right thing and the comment asserted the opposite.
- **7.6** — *"three factually-wrong claims corrected in place"* across both permanent rules documents. Production code
  was not altered by the review at all.

Charlie (Senior Dev): *"We have lint, type-check, unit tests, an E2E suite against the production image, and a manual
browser pass. Not one of them looks at the text that tells the next story what to do — and that text is now the majority
of some diffs."*

### 2. `oversized` fired 6 / 6 and trimmed 0 / 6 — and its replacement may be the same error with the sign flipped

Story 7.15 finally measured a signal that had been carried unread across three epics. The verdict is unflattering to the
signal: Spearman **rho 0.000** against total findings, −0.051 against actionable, −0.103 against medium-plus. The
**smallest** spec (6.2, 2726 tokens) produced the **most** findings — 23 — and five of Epic 6's six
"assertions that could not fail."

But the replacement threshold, 6000 tokens, is a population calibration on **n = 6**, set **0.7 % above** a figure the
record itself calls an inflated upper bound, and it is projected to fire **0 / 6**. Identical information content,
opposite sign. And it is not mechanically enforced: `step-02-plan.md` instruction 6 still hardcodes *"exceeds 1600
tokens"*, and precedence between a hardcoded step instruction and a `persistent_facts` entry is undefined. The encoding
was proved *resolvable and consumed*; it was never proved *effective*.

Amelia (Developer): *"And the story then closed every ledger row that would have caused anyone to look. That is the
exact failure mode the story exists to correct, one level up."*

**`followup_review_recommended` has now fired 15 / 15.** Same shape, unexamined.

### 3. The `createUserViaUi` defect is unfixed — only its data was removed

The `AdminUsers` query is unpaginated. At 5497 rows a no-other-load probe measured the create-user dialog taking **5015
ms** against that assertion's **5000 ms** timeout, and the table grows ~120 rows per full suite run. It stopped being a
flake and became a countdown.

It halted Story 7.9 mid-flight and forced a control run — the tree checked back out at the 7.8 commit, `npm ci` back to
Vite 7, image rebuilt — to prove the bump was inert with respect to the suite. That investigation was done well. But the
fix was a database clear, and the clock restarted.

Two corrections the review forced onto the record are worth preserving: the failure is **size-driven and
load-sensitive**, not deterministic or monotonic (two full green runs happened at larger row counts than a preceding red
one in the same pass), and the Vite 7 control run the first draft credited with settling attribution had **no
discriminating power** — it ran at the largest DB with both sides saturated at 8/8 failures. What actually settled it
was two consecutive green runs on the unchanged Vite 8 tree after the reset.

`md` has routed pagination to backlog as a product feature request. **The gate half remains owed** and is tracked
separately (**D4**).

### 4. Instruments credited with discharging acceptance criteria did not exist

Story 7.14's maskable-icon safe-zone checker — the instrument the record credits with discharging AC2 — existed only in
a **deleted `.tmp/` script**. The review rebuilt it as a real gate in `e2e/support/png.ts`. The icon generator was not
committed either; committing it (`scripts/generate-icons.sh`, `npm run icons`) immediately **exposed a second defect**:
ImageMagick writes `tIME` plus three `tEXt` timestamp chunks, so the recipe produced different bytes on every run.
`-strip` fixed it and the maskable icon was regenerated, pixels unchanged.

Dana (QA Engineer): *"An AC discharged by something unrepeatable is an AC discharged by a claim."*

### 5. A user-visible behaviour shipped opposite to its own requirement prose

`registerType: 'autoUpdate'` calls `window.location.reload()` on worker activation, and `isExternal` means a **second
tab** triggering the update reloads this one. This app is explicitly multi-tab with live subscriptions, so a deploy
discards whatever the user had typed into the item field, the list-name dialog or the change-password form. The
requirement said updates are *"picked up silently on the **next launch**"*. They are not.

Found only at review, in `node_modules`, by reading the plugin's own client code. The comments in `src/main.tsx` and
`vite.config.ts` were corrected; the behaviour was deliberately left, because suppressing it deviates from the mechanism
the epic mandates by name. **`md` has now accepted it as shipped** (see Decisions).

Alice (Product Owner): *"The code was right and the documentation was wrong in the opposite direction. That is the worst
possible orientation for a defect, because the documentation is what the next person trusts."*

### 6. Vite 8 silently raised the shipped browser floor, and no gate could see it

chrome 107 → 111, edge 107 → 111, firefox 104 → 114, safari 16 → 16.4, plus a **new ios 16.4 floor**, and minify
switched to oxc. Measured from both packages, invisible to every gate here because Playwright is Chromium-only. Accepted
as a normal major consequence and recorded as a decision — but it was found at review, not at the gate, and Story 7.14
then turned this into an installable **mobile** app.

### 7. A prediction in the ledger was measured false, and the underlying skew is permanent

Story 7.7 filed the split Kotlin runtime (`kotlin-stdlib` 2.4.0 against `kotlin-reflect` 2.3.21, introduced by
`arrow-core` 2.2.3) with **Story 7.12's Kotlin bump named as the dissolving fix**. Story 7.12 measured that prediction
false: reflect is still 2.3.21 against stdlib 2.4.10, now one patch wider. Cause traced rather than guessed — the Kotlin
Gradle Plugin injects `kotlin-stdlib` at the compiler version but **never injects `kotlin-reflect`**, and the unmoved
2.3.21 request is declared by `io.ktor:ktor-server-core-jvm:3.5.2`. **No Kotlin bump can ever close this.**

Winston (Architect): *"Good that we traced it. The lesson is that a ledger entry which names its own fix is a
prediction, and predictions in the ledger need to be marked as such."*

### 8. The ledger gained 144 entries and no story drained it

Filing is working — genuinely well, and it is why this retrospective could be written from evidence. Draining is not
demonstrated. Epic 7 contained no triage pass, and the file is now long enough that its own readability is a risk.

## Cross-Story Technical Patterns

**Reviews found what gates structurally cannot see.** Documentation inversions, a raised browser floor, a
non-deterministic asset generator, an instrument that did not exist, a recovery command that could not work, a ledger
action aimed at a CI pipeline that does not exist. None of these are code defects and none is reachable by any gate the
project runs.

**"Routed from a measurement taken in this pass, never from the spec's numbers."** This phrase recurs across the
dependency stories and it is the reason the epic survived its own planning going stale mid-flight.

**Green-first-try became the norm after 7.3.** 7.8, 7.10, 7.11 and 7.13 each hit `retries: 0` green at both ends of
their pass without a re-run. Before 7.3, a baseline run routinely needed a second invocation.

**Deliberate non-actions were recorded rather than omitted.** 7.12 tested the spec's conditional catalog entry and did
not add it, and said so. 7.11 stated why no screenshot pass was taken and why `:bp_back:test` was out of gate. 7.12
stated that no lower Kotlin ladder rung was ever walked and that there is therefore no rejection symptom to record. This
is a real discipline improvement and it is what made the records auditable.

**Scope-bleed was refused correctly, and it cost something.** Story 7.11 declined to fix another story's stale ledger
entry (a now-inaccurate advisory count) because reconciling another story's entry is scope bleed. Right call by the
rule; the residue is that the ledger carries known-stale text on purpose.

## Key Insights

1. **Encoding a retro item as a named story slot is the difference between 0 / 7 and 6 / 6.** Tested in both directions
   now. It is a mechanism question, not a discipline question, and it is settled.

2. **Our gates cover code. Nothing covers the authoritative prose the next agent reads as binding** — and in several
   stories that prose was ~80 % of the diff and contained factually false prescriptions. This is the single largest
   uncovered surface in the project.

3. **A measured, reproduced hold beats a bump.** Story 7.10 moved no version and produced more durable knowledge than
   most landed upgrades did — because the symptom was reproduced in the real tree, the workaround was refused on named
   costs, and the revert was verified.

4. **A defect whose *data* was removed is not fixed.** `createUserViaUi` will return on a schedule of roughly 120 rows
   per suite run.

5. **A signal that fires every time is the same as a signal that never fires.** `oversized` fired 6 / 6 and trimmed 0 /
   6. `followup_review_recommended` has now fired 15 / 15. Measuring the first one was one of the epic's best pieces of
   work; the second is sitting unmeasured in exactly the same posture.

6. **Device-class verification gets discharged by `md` doing it, never by scheduling it.** Twice now — real-device HTTPS
   auth at the Epic 6 retro, and the PWA install at this one. That is not a failure mode to fix; it is the route that
   works, and it should be planned for rather than deferred into a story that cannot execute it.

## Team Agreements (updated)

Carried forward unchanged:

- **E2E tests are UI tests.** API calls permitted only for environment preparation.
- **Every E2E test names its FR (s)** in the title.
- **A story is not `done` until E2E coverage exists for its critical user-facing path**, desktop **and** mobile, against
  the production image.
- **Manually exercise each flow in a real browser before writing its E2E.**
- **A new test is unproven until it has been observed failing** — break the behaviour, confirm red on both projects,
  restore. *(Held this epic. 7.11 and 7.14 applied it without being asked.)*
- **Deferred/tracked debt goes in `deferred-work.md`.**
- **Previous retro action items reviewed at the start of every retro before new items are added.**
- **A retro action item must become a story or an acceptance criterion.** *(6 / 6 this epic. Settled.)*
- **Backend changes require an explicit `md` unfreeze**, never an inline workaround. *(The scoped unfreeze held: only
  7.4, 7.6 and 7.12 touched `bp_back/` or `gradle/`, each naming its files.)*
- **New FRs authored during planning are added to `prd.md` in the same pass.**
- **Reconcile `sprint-status.yaml` at story close**, whichever dev workflow ran.
- **Never infer production configuration from this repo.**

New from Epic 7:

- **Never quote a version, a line number or a count from a planning document — re-measure it in the pass.** Every
  dependency story diverged from the epic's named versions, and 7.2 and 7.4 found planning figures materially wrong.
  Record the divergence; do not silently absorb it and do not silently follow the stale number.
- **A ledger entry that names its own fix is a prediction and must be marked as one.** Story 7.7 named 7.12 as the
  dissolving fix for the split Kotlin runtime; 7.12 measured that false and traced a cause no bump can close.
- **An instrument that discharges an AC must be committed, not run from a scratch path.** If the record credits a script
  with proving something, the script is part of the deliverable — and it must be deterministic.
- **Prose is part of the diff and is not covered by any gate.** Treat ledger, rules-file and spec text with the same
  suspicion as code, because the next agent treats it as binding.
- **A verification that needs hardware this run does not have is a scheduling item for `md`, not a documentation item.**
  File it as owed with a named owner, never as "not scheduled".
