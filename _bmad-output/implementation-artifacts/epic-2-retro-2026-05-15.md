## What Went Well

### Story-to-story knowledge transfer was effective

Key discoveries in 2.1 (Java file for `GraphQLError`, `UUIDMongoSerializer` not `UUIDSerializer`, `find()` returns
`Flow`) were documented and pre-loaded in subsequent story dev notes. Neither issue was re-discovered in 2.2 or beyond.

### Review patch count improved story-over-story

2.2 had 10 patches → 2.3 had 5 patches → 2.4 had 0 patches. Lessons from each story's review were absorbed within the
epic.

### Architecture decisions held cleanly

GQL for admin operations (not REST) was applied consistently across 2.1, 2.2. The `AtomicReference` config cache
pattern, `GraphQLForbiddenException` Java file, Arrow `Either` for service errors — all established in 2.1 and reused
without re-derivation.

### Story 2.0 debt cleanup executed immediately

The Epic 1 retro decision to remove `UserStorage` before any new features was acted on as the first story. Eliminated
the TOCTOU risk and the dual-map pattern before building on top of them.

### `GQL_CALL_PRINCIPAL` Principal exposure: completed

The Epic 1 action item to expose the JWT principal via `CustomGraphQLContextFactory` was done. Admin authorization is
consistent and required zero extra wiring in stories 2.2, 2.3, 2.4.

### Two significant latent bugs caught in review (not in prod)

- `UUIDMongoSerializer.deserialize()` would fail on cold-cache load after server restart (BSON String handling) — fixed
  in 2.1 review
- `deleteById` ignoring `DeleteResult` — concurrent delete would return false success — fixed in 2.2 review

### Golden path manually verified by md

End-to-end: admin panel user management, registration toggle, adaptive login screen — all working correctly.

## What Didn't Go Well

### Epic 1 unhappy-path checklist action item: not completed

The action item "Add design checklist for unhappy-path and error handling coverage before the first Epic 2 story" was
committed to in the Epic 1 retro. It was not demonstrably implemented. The same category of issues recurred in 2.2 and
2.3:

- `UUID.fromString()` throwing uncaught `IllegalArgumentException` (2.2)
- `ConfirmDialog` closing unconditionally on mutation failure with no user feedback (2.3)
- No client-side validation on empty username/password submit (2.3)
- Cancel button remaining interactive during in-flight mutation (2.3)

### Epic 1 regression tests for concurrency fixes: not completed

Story 2.0 renamed the persistence test but did not add regression tests for the `UserService` TOCTOU fix or the Apollo
concurrent refresh race fix. Two concurrency bugs remain covered only by "it worked at the time."

### E2E coverage didn't keep pace with UI stories

Stories 2.3 and 2.4 delivered significant UI — admin user management, registration toggle, adaptive login. No E2E tests
were written for these flows within the epic. The gap was flagged and punted to Epic 3.

### `deferred-work.md` is accumulating without triage

25+ deferred items now span both epics. Some are benign style notes; others are real UX bugs (e.g. `/auth/register`
accessible when registration is disabled — user sees full form, submits, gets opaque error).

## Key Insights

1. **The review process catches what design should prevent — again.** The positive trend (10→5→0 patches) shows the team
   absorbs lessons story-over-story, but the starting count in 2.2 was still too high. A design-time checklist for error
   paths would front-load that work.

2. **Action items need an owner and a verification step.** Two of four Epic 1 action items weren't completed. The retro
   process only has value if commitments are tracked and checked. Future action items should be verified at the *start*
   of the next retro before new items are added.

3. **E2E stories belong inside the epic, not after it.** Stories 2.3 and 2.4 shipped without E2E coverage. Treating E2E
   as a cleanup task in the next epic means the UI is unverified at "done." Any epic with significant UI stories should
   include a paired E2E story as part of epic completion.

4. **`__generated__/` is sacred — codegen only.** The `src/__generated__/` directory must never be manually edited.
   Schema changes → run `npm run generate` → commit the generated output. This is a hard rule, not a guideline.

5. **Gradle wrapper root location bites repeatedly.** The correct invocation is `../gradlew` from within `bp_back/`. A
   Gradle MCP server is worth evaluating to eliminate the cognitive overhead entirely.

---

## Team Agreements (New)

- **`__generated__/` is read-only** — never manually edited; always regenerated via `npm run generate` after schema
  changes
- **Every epic with significant UI stories includes an E2E story** — planned at epic kickoff, not retrospected after
- **Action items from the previous retro are reviewed at the start of every retro** before new items are added
