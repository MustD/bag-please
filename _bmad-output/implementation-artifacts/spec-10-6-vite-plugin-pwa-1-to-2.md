## Intent

**Problem:** `vite-plugin-pwa` is pinned at `1.3.0`; `2.0.0` (2026-10-03) is the latest stable major. Until it moves (or is held with evidence) the frontend is not on a current stack, and people with the app installed must not notice the move.

**Approach:** Move the pin `1.3.0` -> `2.0.0` alone (re-measure first; target any newer stable), install with a plain `npm install`, make only config edits a captured break forces, gate on lint/build/`dist/` artefacts/full E2E, and prove a 1.x-installed worker is replaced cleanly by a 2.x deploy. HOLD (byte-identical revert + ledger) if it cannot land cleanly.

## Design Notes

The plugin's shipped code did not change between 1.3.0 and 2.0.0, so the risk sits in the lockfile (transitive churn) and in the deploy-over-install path. When the two builds produce a byte-identical `sw.js`, a browser's update check finds nothing new — that is the correct outcome, but it proves nothing about replacement. The marker build forces a real worker update across the 1.x -> 2.x boundary, so the `autoUpdate` reload path is observed, not assumed.
