## What Went Well

### The backend freeze held completely

Zero files under `bp_back/` changed across seven stories, git-verified in each. Every story carried a **Block If**
escalation path instead of a workaround. It was exercised honestly: Story 5.5 hit FR34's optional list description,
found no `List.description` field in the frozen schema, and **refused to ship it** — recording the deferral rather than
hacking around the contract.

### E2E went from zero to a real gate — against the production artifact

Epic 4's fatal flaw was "TypeScript compiles" being accepted as "works". Story 5.1 closed that structurally:
`webServer: docker compose up -d --build`, `baseURL: http://localhost:2080`, and **two mandatory projects** — desktop
Chrome *and* Pixel 7, because Epic 4's regression was mobile-only. Every subsequent story inherited a gate it could not
quietly skip. The suite grew monotonically, story by story, to 32 specs / 64 runs.

The topology choice is the load-bearing part: tests run against the **built bundle served by Caddy**, not a dev server.
That closes the whole build-only failure class (asset hashing, base path, tree-shaking, SPA-fallback misconfig).

### "Manually exercise in a real browser, then write the test" earned its keep three times

- **5.2** — the login branch shipped `try { … } finally` with **no `catch`**, so a failed login threw out of the handler
  instead of rendering the inline error. Found by hand, before any test existed.
- **5.3** — the change-password confirmation never rendered: react-router 7 defers imperative `navigate()` under
  `startTransition`, so `clearAuth()`'s urgent re-render committed first and RouteGuard's own redirect won the race.
  `flushSync` couldn't fix it (a transition can't be flushed). Diagnosed only by instrumenting a live browser.
- **5.4** — graphql-kotlin's `Exception while fetching data (/field) : …` wrapper was leaking into a user-facing dialog.

None of these were reachable from type checks or unit tests.

### Conventions compounded instead of resetting

Each story's "Previous Story Intelligence" section carried forward *specific, file-cited* learnings from the last one,
and the review severity curve shows it working: by Story 5.7 all six findings were **low**. The standing conventions
that emerged — real `catch` on every async branch, same-tick `if (loading) return` re-entry guard, `helperText ?? ' '`
to reserve layout space, never bucket a loading `null` with a `false`, errors inline never as toasts — were each paid
for once and then prevented repeats.

### Architecture simplification is real, not cosmetic

Caddy upgrades WebSockets automatically (nginx needed explicit directives); `handle` blocks are source-ordered so
`/api/subscriptions` before `/api/*` is self-documenting. Dropping SSR removed `ApolloNextAppProvider`,
`SSRMultipartLink`, and `@apollo/client-integration-nextjs` entirely. The security posture improved as a deliberate
choice: the old app kept the access token in `localStorage`; the reframe holds it in memory only.

### The dev-auto flow accelerated the back half sharply

Stories 5.5–5.7 — lists management, the shopping view with per-list real-time, and two-actor sharing/membership — all
landed between 07-21 and 07-23 on ~160-line spec files with an embedded review-triage loop, versus 303–567-line story
files plus a separate review workflow for 5.1–5.4.

## What Didn't Go Well

### The FR9 automated E2E fell out of the tracking system

This is the epic's most instructive failure. The 401 → silent-refresh → refresh-fail → `/auth?expired=1` path was:

1. **5.2 AC#7** — deliberately deferred, explicitly labelled *"tracked debt, not FR9 fully E2E-covered"*, because 5.2
   issued no GraphQL query that could produce a 401.
2. **5.3 Decision #4** — re-deferred; the clean sign-out redirects too fast to fire the path organically.
3. **5.4 Decision #8** — 5.4 was the first query-bearing story, so the debt became *organically exercisable*. It was
   raised as an explicit **"Open question for `md`"**… which was never answered.
4. **5.5 / 5.6 / 5.7** — the dev-auto specs **do not mention FR9 at all.**

The item did not survive the handoff between two workflows. It was tracked in a story-file field that the spec-file flow
does not read, and it was never written to `deferred-work.md` — the one ledger both flows share. Nobody dropped it
deliberately; the process simply had no place to keep it.

### The shared `registrationEnabled` flag flake was accepted five times instead of fixed once

`registrationEnabled` is a single Mongo document, and `chromium` + `mobile` run concurrently against one backend. The
admin toggle test flips it for real, and the brief OFF window can break the register-based specs in the other project.
Trail: designed around in 5.2 → decision "keep the real flip + CI retries" in 5.4 → *"1 flaky, retry-healed"* reported
in 5.5, 5.6, **and** 5.7. Each report was individually reasonable; collectively it's a fix that was never scheduled.
`retries: 2`
in CI is masking a known race rather than resolving it.

### `project-context.md` was known-stale for four stories and warned about instead of fixed

From Story 5.3 onward, every story record carried a variant of *"project-context.md's frontend section is stale — it
documents the removed Next.js/nginx stack; trust the live code."* That warning was written three times (5.3, 5.4, and
via the 5.5 spec's code map) at real token cost, while the two-minute fix went undone. Documentation drift that agents
route around is documentation drift that compounds. **Fixed as part of this retro.**

### Epic 4's core verdict is materially better but not formally discharged

The app is dramatically more verifiable than at the end of Epic 4 — 64 E2E runs including a mobile viewport, versus
zero. But: it is **still not deployed**, and the **real-device HTTPS auth sign-off** assigned to `md` in Stories 5.1/5.2
has no recorded result. The mechanism to do it now exists (`E2E_BASE_URL=https://bag-please.localhost`, delivered by
`spec-ssl-termination-single-entrypoint`, commit `6b141e3`) — it just hasn't been exercised on a physical phone. Epic
4's
"mobile login broken on a real device" finding therefore remains *unrefuted* rather than *fixed*, even though the
emulated Pixel-7 gate is green.

### Sprint tracking drifted because the dev-auto flow doesn't own it

All three dev-auto specs state *"`sprint-status.yaml` was not modified (sprint tracking is owned by a separate flow)."*
Result: `epic-5` sat at `in-progress` with all seven stories `done`, and there was **no `epic-5-retrospective` key at
all** — the retro workflow's own status target didn't exist. Corrected in this pass.

### Unexamined signals

All three dev-auto specs carry `warnings: [oversized]` in their frontmatter. Nobody looked at what that threshold means
or whether it degraded anything. Worth one deliberate look before the next dev-auto run rather than another three
ignores.

## Cross-Story Technical Patterns

### Bug classes that recurred (and how they were closed)

| Pattern                              | Stories                       | Resolution                                                                                                                                                                                                    |
|--------------------------------------|-------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Loading `null` bucketed with `false` | 5.2 (shipped) → 5.3, 5.4, 5.6 | Became a named convention after one real bug: guard the `null` case explicitly. Prevented 3× afterward.                                                                                                       |
| Redirect-owner race (react-router 7) | 5.1, 5.3                      | Structural rule: **RouteGuard is the single owner of redirect-to-`/auth`**; signals ride as AuthContext flags (`expired`, `passwordChanged`), never as a competing `navigate()`.                              |
| Post-mutation refetch error handling | 5.4, 5.5, 5.7                 | Convention: success → `reset()` → `onClose()` → `void onDone().catch(()=>{})`; **a failed refetch must never be reported as a failed mutation.** One residual deferral in 5.7 (failure path doesn't refetch). |
| Missing `catch` / double-submit      | 5.2 (shipped) → 5.3+          | Real `catch` on every branch + same-tick `if (loading) return`. Cited in every later story.                                                                                                                   |
| Dialog state stale on reopen         | 5.4, 5.5                      | 5.4 patched the same-user reopen case; 5.5's `ConfirmDialog` retains title/description through MUI's close transition.                                                                                        |
| Cross-user cache leakage             | 5.6                           | Apollo `lists` cache was never cleared on logout → a second user in the same tab was mis-redirected to the first user's list. Fixed with `clearStore()` on the logout transition.                             |

### MUI v9 / stack friction worth remembering

- `Switch`'s `slotProps.input` is strictly typed and rejects `data-testid` — testid goes on the root, E2E reaches the
  checkbox via `[data-testid="…"] input`.
- Inputs use `slotProps={{ htmlInput: { 'data-testid' } }}` (v9 slot API), never legacy `inputProps`.
- `react-hooks/set-state-in-effect` (plugin v7) forced render-phase adjustment / query-derived state instead of
  `useEffect` state-sync — a genuine improvement, not just lint appeasement.
- `@vitejs/plugin-react@6` requires Vite 8; pinned to plugin v5 with Vite 7.3.x.
- TS 6 deprecates `baseUrl`; `paths` resolves without it under `moduleResolution: bundler`.
- Access tokens live ~15 min, so `codegen.ts` reads a run-time-minted `CODEGEN_TOKEN` instead of a committed JWT.

### Real-time design notes worth preserving

`subscribeToMore` on the parent `useQuery` (never a second client, never a parallel `useSubscription`). The merge must
be **idempotent** because the backend echoes the caller's own actions, and a `SAVED` event can carry `deleted === true`
(one-timer check-off): key by id, `DELETED` or `SAVED && deleted` → remove, else replace-or-append. FR53 (socket closes
on logout) relies on `subscribeToMore` lifecycle teardown plus the lazy graphql-ws client — deliberately **not** a
permanent `dispose()`, which would break re-subscribe after re-login without a reload.

## Key Insights

1. **A gate wired into config outlives a gate written into an agreement.** Epic 4 had a team agreement requiring E2E on
   UI stories and violated it on all four frontend stories. Epic 5 put the same requirement in `playwright.config.ts`
   and hit it seven for seven. Encode enforcement in the artifact, not in the intention.

2. **Test the shipped artifact, not the convenient one.** Running E2E against the production Caddy image from Story 5.1
   made "done" mean "the bundle users get works" for the whole epic, at the cost of an image build before a cold run.

3. **Two workflows in one epic will drop something.** The FR9 debt was tracked in a story-file field, and the switch to
   spec-file dev-auto silently orphaned it. Cross-workflow debt must live in a shared ledger (`deferred-work.md`), never
   only in a story's prose.

4. **An "accepted flake" is a decision with an expiry date.** Re-accepting the same race five times is not risk
   management, it's deferral by habit. The second re-acceptance should have created a scheduled fix.

5. **Stale docs that agents route around cost more than stale docs that break things.** Four stories paid to warn about
   `project-context.md` instead of one story paying to fix it.

6. **Refusing scope is a deliverable.** Story 5.5 declining to ship FR34's description field — rather than reaching into
   the frozen backend — is exactly the behavior the freeze was meant to produce.

## Team Agreements (updated)

Carried forward unchanged:

- **E2E tests are UI tests.** API calls permitted only for environment preparation. No API-only assertion paths.
- **Every E2E test maps to one or more FRs**, named in the `describe`/`test` title.
- **A story is not `done` until E2E coverage exists for its critical user-facing path.**
- **Manually exercise each flow in a real browser before writing its E2E.** (Paid for itself 3× in Epic 5.)
- **Unhappy-path checklist in every story.**
- **Previous retro action items reviewed at the start of every retro before new items are added.**

New from Epic 5:

- **E2E runs against the production artifact**, on desktop **and** a mobile viewport. Both projects are mandatory.
- **Deferred/tracked debt goes in `deferred-work.md`, not only in a story file** — so it survives a change of dev
  workflow. Any item deferred "to a later story" must name the ledger entry.
- **A flake may be accepted once with a recorded reason; the second re-acceptance creates a scheduled fix instead.**
- **When a story finds a project doc stale, fixing the doc is in scope for that story.** No more warn-and-route-around.
- **`sprint-status.yaml` is reconciled at story close** regardless of which dev workflow ran.
