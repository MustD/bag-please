`/lists/:id` only; the identical construct is untouched on `/list/:id`. **Measured by this retro, 2026-09-11, production
image, `documentClientWidth` 320:** the item name
`Semi-skimmed organic pasteurised milk two litre bottle` renders `scrollWidth 410` vs `clientWidth 71` —

**F3 — `expectInsideViewport` measured one axis and had never been observed failing. (CONFIRMED — and FIXED in this
retro at md's direction)**
*Converged: verification-gap + adversarial + edge-case (twice).*
Source: `bp_front/e2e/support/layout.ts:96-137`. It is the **sole** gate for NFR-E8-1's third clause ("no
interactive control is pushed off-screen") and carries 15 call sites, including the three Story 8.6 category-row
controls at `narrow-viewport.spec.ts:762+` — the exact failure shape its own header says it exists for.

Two defects, both confirmed by reading it, and both failing **open**:

1. **One axis.** It asserted `box.x` and `box.x + box.width` only. A control pushed off the top or bottom passed.
2. **The wrong box.** It compared against `document.documentElement.clientWidth` — the viewport — so a control
   clipped away by an `overflow: hidden` ancestor kept a bounding box squarely inside the viewport and passed.

And it was the only one of the three helpers with no falsifiability control: `grep -rn "rejects.toThrow" bp_front/e2e/`
returned exactly three hits, all for its two siblings.

*Correction to the initial reading:* the verification-gap lens cited `narrow-viewport.spec.ts:363-372` — where
`expectInsideViewport` was tried at the Story 8.2 review and passed — as evidence the helper might be inert. Read in
full, that note says something narrower and correct: containment is the **wrong assertion for a clipping defect**,
because the text spills invisibly behind `overflow: hidden` and the element never leaves the viewport. It is not
evidence either way about the helper. The real evidence is the absent probe, and that stands. The note has been
annotated in place so it is not misread again.

**RESOLVED 2026-09-11.** Rewritten on `toBeInViewport({ratio: 1})`, which closes both gaps at once: Playwright backs
it with an IntersectionObserver, whose intersection rect is clipped by every intermediate `overflow` ancestor as well
as by the viewport, and is computed in both axes. `ratio: 1` is what makes it "fully inside" rather than the default
"touching at all". It also auto-retries, where the old one-shot `boundingBox()` read whatever geometry existed at
that instant. Three falsifiability controls added beside its siblings' — horizontal, vertical, and clipping-ancestor.

**Verified by mutation, not by reasoning.** With the old x-only implementation restored, the VERTICAL and
CLIPPING-ANCESTOR controls both fail (no throw to catch) and the horizontal one still passes — the two new controls
map exactly onto the two defects. With the fix in place: `npm run lint` 0, `tsc -b` 0, full suite **208 passed, 22
skipped, 0 failed**, all 15 existing call sites still green under the stricter assertion.

**New sub-finding, measured while building the control (now recorded in the spec):** a probe pushed off the *right*
edge does not work, and the reason is a property of the assertion rather than the probe. Widening the document makes
Chromium grow the **visual viewport** to match under this project's mobile emulation — measured with the probe at
`left: 640`: `documentElement.clientWidth` stayed 320 while `window.innerWidth` became 690, and `intersectionRatio`
was legitimately `1`. So on a page that *already* overflows horizontally, containment is measured against the grown
viewport. `expectInsideViewport` therefore does **not** subsume `expectNoHorizontalOverflow` — the two compose, and
the controls use a negative offset instead.

### Defer (tracked, with enough context to act on without re-investigation)

**F7 — the `isPrimary` multi-touch guard is exercised by nothing.** `ListShoppingPage.tsx:90`, `:106`. Every pointer

(`shopping.spec.ts:707`) uses right/middle mouse and exercises the `e.button !== 0` half only. No test in the repo
contains the string `isPrimary`. Delete `|| !e.isPrimary` from both handlers and FR60 stays green.

**F8 — `byCreatedAtAsc`'s NaN guard and id tiebreak are asserted only by construction.** `order.ts:51-59`. Not an
Epic 8 regression — 8.5 moved the function rather than changing it — but 8.5 also created the vehicle
(`e2e/order.spec.ts` imports the module with no `page` fixture), and used it for the sibling comparator's tiebreak
and not this one.

**F9 — the stale-selection prune collapses the whole selection when `categories` is momentarily `[]`. (CONFIRMED — read
at source)**
*Converged: adversarial + edge-case.* `itemFilter.ts` prune vs `ListDetailPage.tsx:61`
(`categoriesResult.data?.getCategories ?? []`). Any state clearing that query's data prunes every selected id —
the wholesale loss the story widened the prune to prevent. The FR61 prune test deletes one of two categories with
data present, so the empty-`categories` path is never entered.

**F10 — no in-flight guard on row activation.** `ShoppingItemRow` `onToggle`/`handleToggle` read `item.checked` from
the cache, which only changes after the round trip, and the row gives no pending feedback. Two taps inside the
latency window compute the same `nextChecked` and fire two identical mutations. The FR60 request-count tests sleep
500 ms between activations, so none can see it.

**F11 — `order.ts`'s "KEEP THIS MODULE IMPORT-FREE" constraint is enforced by a comment.** `order.ts:1-5`. The first
`@/…` import in its transitive graph breaks `tsc -b` for `tsconfig.e2e.json`. It is the shared unit two stories now
build on — exactly the file people will add imports to. An `eslint no-restricted-imports` rule, or `paths` in
`tsconfig.e2e.json`, would make it real.

**F12 — `order.spec.ts` is a unit test inside the production-artifact E2E suite.** It imports `../src/lib/lists/order`
directly, so it asserts against *source* while every sibling asserts against the deployed image — and it boots the
whole Docker stack, twice, for three synchronous assertions. A silent exception to the suite's own invariant.

**F13 — ~20 fixed `waitForTimeout(500|1000)` calls gate the request-count assertions.** `shopping.spec.ts`,
`lists.spec.ts`. A fixed sleep is not a settle: a late request landing after the read makes the test green for the
wrong reason — and the counters are the only thing distinguishing one activation from a double-fire, which is the
defect class they exist for (see F10).

**F14 — `withCategoryMenu` has no `finally`.** `e2e/support/ui.ts`. A `body()` that throws leaves the menu open, and
the next click lands on the backdrop — surfacing as an unrelated failure elsewhere.

**F15 — `registration-toggle-mobile` now renders `/admin` at 320px with no coverage there.** `playwright.config.ts`.
Story 8.1's retarget changed what that project renders at; the floor route sweep visits `/auth`, `/lists`,
`/lists/:id` and `/list/:id` — never `/admin` or `/change-password`. `AdminPage.tsx` renders a three-column table.
The retarget bought no coverage on that surface and can break admin specs for a reason nobody will connect to 8.1.

**F16 — source-comment line references drift. (CONFIRMED — verified against both revisions)**
`bp_front/src/lib/lists/homePath.ts:21` cites `ListDetailPage.tsx:52`. At `014de10^` line 52 *was* the cache-only

the epic. One instance of a class: this codebase carries an unusually high comment-to-code ratio by deliberate house

## Acceptance verdict

**accepted-with-open-items** — criteria **declared**, decided by md at this retrospective.

**Machine reading of the evidence, stated plainly before the decision:** `pending_stories` is empty — all seven
stories are `done` — so nothing forces a rejected verdict. But the epic's declared NFR-E8-1 reads *"Every screen is
usable at a 320px CSS width... no text is clipped **except where a story has measured the clipping and recorded the
decision to keep it**"*, and F1 is unmeasured clipping on `/list/:id`, the screen the app exists for. On the
strictest reading of the declared criteria, that criterion is not met.

**md's decision: accepted-with-open-items.** The reasoning the evidence supports: report #2 as written names the
management screen, and the management screen is demonstrably fixed; each story met its own written scope; and F1 is
a gap between a story's scope and the epic's NFR rather than a story failing its acceptance criteria. F1 and F2 are
tracked as open items 2 and 3.
